# ANQR Governance

## 1. Directory Overview

This directory contains governance automation modules for the ANQR (Agentic Number Query Runner) harness. It manages issue-state policy, corrective flow, and guarded machine/human lane control. The governance layer ensures code quality standards are maintained by monitoring harness health checks and automatically creating or updating Linear issues to track and escalate failures.

## 2. File Summaries

### Facade Module

- **linear-guardian.mjs** - Auto-generated facade that re-exports from `./linear-guardian/index.mjs` and `./linear-guardian/runtime.mjs`. Provides the CLI entry point for the Linear Guardian governance automation.

### Subdirectory

- **linear-guardian/** - Contains the core governance implementation:
  - **index.mjs** - Facade index exporting all public API members including `main`, `processFailingCheck`, `checkStaleIssues`, `printSummary`, and utilities like `buildIssueTitle`, `buildIssueBody`, `buildCommentBody`, `isStale`, `issueNeedsLabelHygiene`, `mergedLabelIds`, plus constants `ROOT`, `REPORT_PATH`, `CHECK_METADATA`, and `actions`.
  - **runtime.mjs** - Runtime carry-forward that imports and executes the main function via `await main()`.
  - **main.mjs** - Main orchestration module that reads the harness report, identifies failing checks, processes each failure, checks for stale issues, and prints a summary. Supports `--dry-run` flag.
  - **process-failing-check.mjs** - Core logic for handling failing checks. Creates or updates Linear issues based on check failures, enforces label hygiene, and respects queue depth limits.
  - **check-stale-issues.mjs** - Detects and escalates stale "In Progress" issues that haven't been updated within the stale threshold.
  - **check-metadata.mjs** - Metadata configuration for each check type with summaries, priorities (1-4), and extra labels.
  - **build-issue-body.mjs** - Constructs Markdown body for new Linear issues.
  - **build-issue-title.mjs** - Builds issue title using `TITLE_PREFIX` from symphony-config.
  - **build-comment-body.mjs** - Constructs comment body for existing issues.
  - **is-stale.mjs** - Stale detection utility comparing issue update time against threshold.
  - **issue-needs-label-hygiene.mjs** - Checks if issue has all required labels.
  - **merged-label-ids.mjs** - Merges existing and required labels with deduplication.
  - **log-action.mjs** - Logging utility that records actions to the actions array.
  - **print-summary.mjs** - Prints summary of actions taken, counting by action type.
  - **actions.mjs** - Mutable array storing all performed actions.
  - **logger.mjs** - Shared logger module using `../../lib/logger.mjs`.
  - **root.mjs** - Path resolution utility for project root.
  - **report-path.mjs** - Path constant for harness report (`reports/latest.json`).
  - **dirname.mjs** - Node.js `__dirname` polyfill for ESM compatibility.

## 3. Overall Directory Function

The governance directory serves as an automated quality enforcement layer. The Linear Guardian monitors harness health checks (typecheck, lint, tests, etc.) and automatically creates or updates Linear issues to track failures.

The workflow: `main.mjs` reads the harness report from `reports/latest.json`, processes failing checks via `processFailingCheck`, checks for stale "In Progress" issues, and prints a summary. The module respects queue depth limits (`TARGET_MAX`) to avoid overwhelming the system and supports `--dry-run` for testing.

Key features:

- Automatic issue creation for failing checks
- Comment updates for recurring failures
- Label hygiene enforcement
- Stale issue detection and escalation
- Dry-run support for testing

## 4. Usage Instructions

### Running Linear Guardian

```bash
# Via facade (recommended)
node ops/governance/linear-guardian.mjs
```

Or directly:

```bash
node ops/governance/linear-guardian/runtime.mjs
```

### Dry Run Mode

To test without making actual Linear API calls:

```bash
node ops/governance/linear-guardian/main.mjs --dry-run
```

### Prerequisites

- A valid harness report at `reports/latest.json` (generated by `harness-report.mjs`)
- Linear API credentials configured
- Required labels defined in `symphony-config.mjs`

### Output

Actions are logged with icons:

- `create` (New issue created)
- `comment` (Added comment to existing issue)
- `hygiene` (Labels enforced)
- `skip` (Queue full, skipped)
- `stale` (Stale issue escalated)
- `info` (Informational message)

A summary is printed showing counts by action type.

## 6. Additional Comments

- **Fail-Safe Design**: Module checks queue depth before creating issues to avoid overwhelming the system. If `currentDepth >= TARGET_MAX`, new issue creation is skipped.

- **Dry-Run Support**: All Linear API modifications can be tested via `--dry-run` flag without executing actual API calls.

- **Label Hygiene**: Automatically enforces required labels on existing issues missing them.

- **Stale Detection**: "In Progress" issues not updated within `STALE_THRESHOLD_MS` receive escalation comments.

- **Source Tracking**: Issues created by Linear Guardian are marked with `source: "linear"` in Symphony state for worktree routing.

- **Priority Mapping**: Check failures are assigned priorities: P1 for test-unit (critical), P2 for repo-structure/typecheck/depcruise/ollama-health/litellm-routing (high), P3 for lint (medium), P4 for docs-freshness (low).
