# OOM Fix — 2025-03-30

## Problem

`systemd-oomd` killed `anqr-codebuff-bridge.service` due to excessive memory usage:

```
Current Memory Usage: 4.6G
Memory Pressure Limit: 0.00%
Pressure: Avg10: 52.53 Avg60: 30.44 Avg300: 8.93
```

## Root Causes

1. **Excessive heap allocation**: `--max-old-space-size=4096` (4GB) allowed Node.js to grow unbounded
2. **No periodic GC**: Memory accumulated without cleanup between requests
3. **Provider probe feedback loop**: Continuous probes sent results to Discord → triggered more bridge requests → more probes → OOM
4. **No concurrency limits**: Both bridges had inadequate limits (codebuff-bridge had 5, symphony-bridge had 8)

## Resolution

### 1. Reduced heap size (both bridges)

**Before:**

- `--max-old-space-size=4096` (4GB heap)
- `MemoryHigh=5120M`, `MemoryMax=6G`

**After:**

- `--max-old-space-size=2048` (2GB heap)
- `MemoryHigh=3G`, `MemoryMax=3584M`

**Rationale:** 2GB is sufficient for bridge workloads. The 4.6GB usage indicated a leak, not legitimate need.

### 2. Added periodic garbage collection

Both bridges now run `globalThis.gc()` every 5 minutes with before/after logging:

```javascript
setInterval(
  () => {
    const mem = process.memoryUsage();
    const heapMB = Math.round(mem.heapUsed / 1024 / 1024);
    logInfo(`[gc] Periodic GC: heap=${heapMB}MB`);
    globalThis.gc();
    const after = process.memoryUsage();
    const heapAfter = Math.round(after.heapUsed / 1024 / 1024);
    logInfo(`[gc] After GC: heap=${heapAfter}MB (freed ${heapMB - heapAfter}MB)`);
  },
  5 * 60 * 1000,
);
```

### 3. Fixed provider probe feedback loop

**Problem:** Continuous provider probes sent rankings to Discord via `sendDiscordEmbed()`, which triggered new bridge requests, causing infinite probe cycles.

**Fix:** Disabled Discord notifications during probe cycles. Rankings are now logged server-side only:

```javascript
// SKIP: Don't send Discord notifications during probe cycles
// Provider rankings are logged server-side via logInfo above
logInfo(`📊 Provider rankings logged server-side (not sent to Discord)`);
```

**Locations fixed:**

- `runContinuousProviderProbe()` — Phase 3 ranking notification removed
- Startup exploration — Final ranking notification removed

### 4. Existing concurrency controls validated

- `codebuff-bridge.mjs`: `MAX_CONCURRENT_REQUESTS = 5` ✅
- `symphony-bridge.mjs`: `MAX_CONCURRENT_REQUESTS = 8` ✅

Both already had concurrency limiting that rejects excess requests with HTTP 429.
