# ANQR — Performance & Polish Review · 2026-05-24

A consolidated, ROI-ranked roadmap derived from five parallel agent audits scoped by file ownership (render pipeline, web shell/bundle, API/MCP, UI/UX/a11y, test coverage). Per-area deep dives live in `docs/review-2026-05-24/agent-*.md`.

## Scope and constraints

Every recommendation honours three hard constraints:

1. **QR scan correctness is the product.** Encoding, mask selection, version computation, and `enforceModuleConstraints` are off-limits. Any item touching the render path includes a preservation argument.
2. **88-locale matrix is preserved.** Suggestions to "trim locales" are out of scope.
3. **In-flight files are off-limits** (`ios/App/ci_scripts/`, `capacitor.config.json`, `apps/web/src/features/onboarding/components/welcome-modal.tsx`, `apps/web/src/content/gallery/`, `tools/gallery/prerender-gallery-thumbs.ts`).

Confidence tags: ⚡ measured (numbers from running tools), 🔍 inferred (code reading), 💭 speculative (worth verifying).

---

## What the audit found is already strong

Worth saying first — these don't need touching:

- **Shared render core.** `renderInitialQRCode` and `generateGifAnimationFrames` are genuinely shared between web HTMLCanvas and the Netlify `/api/qr` `@napi-rs/canvas` path. The `ArtworkState.lockedMask/lockedVersion` pattern alone likely saves >80 % of wall time on animated artwork GIFs.
- **Lazy-loading boundaries.** `Analyze`, `Gallery`, `StaticPage`, `WelcomeModal` are all `React.lazy()` with proper `Suspense`. Tailwind v4 auto-purge keeps CSS at ~84 KB.
- **API surface design.** Four-function split (`qr`, `api-qr`, `mcp`, `qr-render-background`), zod-validated `/api/contract/qr` envelope, blob-cache short-circuit, sentinel-gated background re-render — architecture is sound.
- **A11y groundwork.** Skip-link, error boundary with translated fallback, keyboarded mobile divider, render-lifecycle CustomEvents, WCAG contrast badge in-canvas, double-back-to-exit on Android.
- **Unit test depth where it counts.** 21 specs over QR encode internals (masks, penalty, BCH, version selection), 7 colour-primitive specs.

The big gaps are downstream of structural choices (no CI, no permutation harness, no visual regression) — not of careless engineering.

## Medium bets (worth scheduling)

Higher leverage but bigger surface; sequence after the quick wins so the safety net catches regressions.

### S1 · Build the permutation safety net that the audit title asks for (E-R3) · 1–2 days
The `permutations` Playwright project matches zero files. Two-layer fix:
- `tests/e2e/permutations.web.spec.ts` — ~30 representative combos (module style × dither family × animation pattern × frame style), assert `canvas.toDataURL()` hash-equal or `toMatchSnapshot`.
- `packages/domain/qr/src/encode-decode-roundtrip.spec.ts` — 60 combos of `[L,M,Q,H] × [5 module styles] × [3 finder styles]`, encode→render→decode, assert payload equality. Hard-enforces scan correctness.

Without this, every quick-win above is shipped on trust.

### S2 · Short-circuit animated GIF renders to background-only (C-F5) · 1 day
Wrap `netlify/functions/qr/handler.ts`: when `shouldSerializeAnimatedRender(params) && !p.isFullRender`, immediately return a degraded placeholder + trigger the background function. Eliminates the entire 504 class of failures for `/api/qr` without touching render-runtime.

### S3 · Lefthook `typecheck:all`, fix the 67 harness/test typecheck errors (E-R5) · 2–3 h + ongoing
Two-step: change `lefthook.yml:39` to run `typecheck:all && typecheck:tests`; resolve the 67 known errors (90 % non-null narrowing fixes); remove the `harness/**/*.spec.ts` exclusion from `tsconfig.harness.json` so it never regresses.

### S4 · Reorder sidebar, add empty-state for search (D-F9, D-F6) · 1 day
Move Safety section up between Animation and Output so Pro users can fix contrast warnings before exporting. Add a "no matches" card with "Clear search" when filters return zero. Both ship cleanly under existing accordion state.

### S5 · Tier descriptions + in-app re-entry to Welcome modal (D-F5, D-F10) · 1 day
Add `tiers.basicDesc / advancedDesc / professionalDesc` i18n keys describing what each tier unlocks; surface them in the tier `Tabs` and the mobile `Select`. Add a `?` or `Sparkles` icon in the Header that re-opens the WelcomeModal (clear the localStorage key + reload — same code path). Big discoverability lift.

### S6 · Translate the remaining literal strings (D-F8) · 2 h
A handful of hardcoded English strings sit in user-visible chrome (the reset `confirm()`, sidebar aria-labels, "Press back again to exit" Android toast, "Go to X" prefix in mobile nav). Mechanical move through `t()`. Honours the 88-locale constraint properly.

### S7 · Split rate-limit env vars (C-F3) · 30 min
Real correctness bug: setting `MCP_RATE_LIMIT_PER_MINUTE` silently affects `/api/contract/qr` too. Add `API_QR_RATE_LIMIT_PER_MINUTE` with default 60 (matching the policy constant) and keep MCP at 30.

### S8 · A11y live regions on BusyOverlay + clipboard feedback (D-F4) · 1 h
One `role="status" aria-live="polite"` on the BusyOverlay stage container; one hidden `<output aria-live="polite">` near the main region that mirrors stage labels and "Copied/Exported" announcements.

### S9 · Touch targets to 44×44 px (D-F3, D-F12) · 2 h
Sidebar reset/close/search-clear trio is currently 16×16 (below WCAG AA 24×24). Bump to `h-11 w-11` icon buttons on mobile breakpoints, extend mobile divider hit area with padding.

### S10 · Search keywords i18n (D-F1) · 1 day
Move `apps/web/src/features/generator/components/section-keywords.const.ts` to i18n keys (one per section, comma-separated synonyms). Currently only English users get keyword matches; 87 locales lose half the value of the prominent search bar.

### S11 · Per-locale parity test + RTL smoke (E-R9) · 2 h
One unit spec asserting `i18n/locales/<each>.json` key set equals `en-US`. One Playwright spec hitting `/?lang=ar`, asserting `<html dir="rtl">` and canvas still renders.

### S12 · Trim render-pipeline hot loops (A-F2, A-F5, A-F6) · 1 day combined
Wave pattern's per-row `drawImage` (512–1024 calls/frame at 512²), the defensive `if (!errors[ny])` guard in module-level dither, and the `i % width` / `Math.floor(i / 4 / width)` per-pixel computation in `apply-temporal-noise-to-canvas-server.ts`. All numerically identical when rewritten; all on hot paths.

## Long horizon (deliberate work, ship after S-block)

These pay back but need real planning and the safety net above to land first.

### L1 · `apps/web/` unit-test substrate (E-R7) · 2–3 days first slice
Zero specs in the actual product UI. Highest-ROI first targets: pure state functions in `apps/web/src/state/payload-serializers/`, and reducers in `apps/web/src/state/`. Aim ≥ 80 % line coverage on those folders before touching React components.

### L2 · MCP `tools/call` / `resources/read` / `prompts/get` smoke (E-R8) · 1 h
Three tests added to the existing `basic.web.spec.ts` MCP describe block. Closes the MCP-tier gap — currently only `initialize` and `tools/list` are smoke-tested, but the server registers two tools, one resource, and one prompt.

### L3 · Replace contract type-alias specs with one Zod-shape spec per family (E-R11) · 1 day
~95 of the 4830 unit tests are tautological type-alias checks that catch nothing tsc doesn't. Consolidate to one Zod shape spec per family; preserve the safety, lose the noise.

### L4 · Frame-loop contract between client and server (A-F13) · 2–3 days
Client and server frame loops have diverged subtly (where temporal noise applies, watermark application order, color-cycle ordering). Currently working; future effect additions will break parity. Either ADR + tests, or extract a typed `FramePipelineSpec` both implement.

### L5 · SoA refactor of error-diffusion pixel storage (A-F7, A-F12) · 3–5 days
Biggest theoretical render win — but biggest blast radius (every `quantize*Pixel` callback changes signature). Don't take without a profile; the medium-bet trim above probably reduces the marginal payoff.

### L6 · qr-store defaults extraction (B-F6) · 2–3 days
`apps/web/src/state/qr-store.ts` is 1057 lines, mostly inline defaults. Extract `DEFAULT_PAYLOAD / DEFAULT_RENDER / DEFAULT_OVERLAY` into a sibling chunk; the store becomes ~150 lines of pure setters. Saves bytes on first paint and improves maintenance.

### L7 · Move rate-limit state to Netlify Blobs (C-F4) · 1 day
Per-container `Map` makes the limit "approximate." Either upgrade to Blobs for a real ceiling, or document explicitly that it's a defense-in-depth speed bump.

### L8 · Expand `/api/contract/qr` to advertise WEBP / GIF + regenerate OpenAPI (C-F7) · 1 day
The contract endpoint limits format to `["png", "svg"]` while the underlying renderer supports more. Expand the enum to mirror `renderBasicServerQROutput`, regenerate `public/openapi.yaml`. AI agents and SDK clients gain feature parity with `/api/qr`.

### L9 · Perf budget on encode + render (E-R13) · 1 day
`packages/domain/qr/src/encode/qr-encode.bench.ts` and `packages/domain/render/src/render.bench.ts` with Vitest `bench()` and a fixed budget. Catches accidental O(n²) regressions. Defer until L1 lands.

### L10 · Visual regression snapshots wired to Playwright `__snapshots__` (E-R3 part 2) · 1 day
Once S1 lands, commit the 30 PNG hashes / data-URLs to `tests/e2e/__snapshots__/`. CI fails on drift. No more parity-PNGs sitting at the repo root.

### L11 · Drag-and-drop on upload cards or honest copy (D-F7) · 4 h
`file-upload-card.tsx` says "Click or drop" but the surrounding `<label>` has no drag handlers. Implement web-only drop OR change copy to "Tap to upload".

### L12 · Pin `Package.resolved` for iOS Xcode Cloud · gated on you
Currently blocking iOS builds. Either push the file from your MacBook (definitive) or enable automatic SPM resolution in the workflow once that toggle is found in App Store Connect.

## Sequence recommendation

If you actually want to ship this:

1. **Week 1, day 1 (5 hours):** Land the 10 quick wins above. They're independent and stack cleanly. End with a green CI pipeline catching the next regression.
2. **Week 1, day 2–3:** S1 (permutation safety net). Everything after this lands under a real net.
3. **Week 1, day 4–5:** S2, S3 (animated GIF 504 fix, typecheck:all gate).
4. **Week 2:** S4–S6 (UX polish: sidebar reorder, tier descriptions, literal strings translated). User-visible wins.
5. **Week 2 end:** S7–S12 (rate-limit env vars, a11y live regions, touch targets, search i18n, locale parity test, render hot-loop trims). Cleanup pass.
6. **Week 3+:** L-block items, starting with L1 (apps/web unit tests). These need the prior safety net to ship safely.

Three observations across the agents that I'd flag as the meta-story:

1. **The product engineering is good. The CI/safety-net engineering is not.** The 13 render findings are mostly small wins on a solid pipeline; the 14 UX findings are polish on a well-built shell; the 10 API findings are tuning a clean architecture. The 13 test findings are about *absence* — disabled CI, dead Playwright projects, contract specs that catch nothing, 67 typecheck errors that survive every gate. Fix that first or none of the rest is durable.
2. **The biggest single perf win is a one-line fix** (Netlify functions stop bundling 81 MB of public assets per function). That's not a tuning result; it's a quiet bug.
3. **Discoverability is the largest UX gap, not features.** ANQR ships a deep feature set behind a tier system that doesn't describe itself, a search that only works in English, and a welcome modal that can't be reopened. Half a day of i18n + tooltip work makes the existing features visible to the people who already paid the bundle cost to load them.
