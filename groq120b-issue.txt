  Groq's hosted gpt-oss-120b emits tool calls with wrong parameter keys — it has learned
  a different schema than what the symphony bridge advertises.

Impact:
  - Provider skipped in fallback cascade (non-retryable error)
  - Fallback continued to openrouter-openai-gpt-oss-120b-free successfully

Possible fix:
  - Add a tool-call parameter normalizer that maps `cmd` → `command` for exec tool calls
    before validation, OR
  - Exclude groq-openai-gpt-oss-120b from the exec-tool tier so it never receives
    tool schemas it can't reliably call
